On this page

Attention lets each token retrieve information from other token positions. The important change from a fixed-window MLP is not just a larger context: the way information is combined now depends on the input itself. This reading develops that operation, then follows it into a next-token predictor.

1Content-dependent retrieval

A fixed-window MLP gives each relative position a fixed block of weights. In attention, position $i$ instead computes a different set of mixing weights for every input. For “The trophy did not fit in the suitcase because it was too large,” a useful representation of “it” may need information about “trophy.” The architecture provides a route to retrieve that information, even across many intervening positions. Learning a useful route still requires suitable training data and parameters.

Write the input as rows $X\in\mathbb R^{T\times D}$. Each position publishes three vectors:

$$Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.$$

A query describes what a position seeks; a key describes how that position can be matched; a value contains the information it can contribute. All three are learned projections of the same input in self-attention. The matrices are shared across token positions. They are not separate parameters for “trophy,” “suitcase,” or position 8.

Separating keys from values lets the model match on one set of features and retrieve another. For example, keys could encode features useful for locating a noun, while values supply information about its number or meaning. This is an interpretation of their roles, not a guarantee that a particular trained dimension has a human-readable label.

A token vector changes meaning across layersThe input to the first attention block comes from token and position embeddings. In later blocks it is a contextual representation. Two occurrences of the same token can then have different keys and values because earlier layers have processed different contexts.

2Compute one query's answer

For query row $q_i$, first score every key, then normalize across keys, then combine the values:

$$s_{ij}=\frac{q_i k_j^\top}{\sqrt{d_k}},\qquad a_{ij}=\frac{e^{s_{ij}}}{\sum_{r=1}^T e^{s_{ir}}},\qquad y_i=\sum_{j=1}^T a_{ij}v_j.$$

We use $s$ for raw scores and $a$ for normalized attention weights, so the two quantities do not get confused. $d_k$ is the query/key width. Values may have a different width $d_v$; compatible queries and keys must have the same width.

2.1 A complete numerical retrieval

Choose $d_k=2$, $q=[1,0]$, and keys $k_1=[\sqrt2\log2,0]$, $k_2=[0,1]$, $k_3=[0,-1]$. The scaled scores are $[\log2,0,0]$. Their exponentials are $[2,1,1]$, so the weights are $[1/2,1/4,1/4]$.

2.2 How the routing learns

The softmax Jacobian is $\partial a_j/\partial s_r=a_j(\mathbf1[j=r]-a_r)$. Raising one score increases its own weight and reduces the others, because they compete for a fixed total. The value path passes information forward; the query/key path learns how to route it. Both paths receive gradients from the final language-model loss.

A large attention weight alone is not a complete explanation of a prediction: a value can be small, point in an unhelpful direction, or be offset by another head or the residual stream. To test a causal claim about model behavior, changing or removing the relevant input and observing the prediction is more informative than inspecting a weight alone.

Check 1 · Match versus information

If $v_3$ changes to $[0,0]$ while queries and keys stay fixed, what changes? What if we instead add 10 to every score?

Reveal the answer

The weights stay $[0.5,0.25,0.25]$ but the output becomes $[1,0.5]$. Adding a common score shift changes neither weights nor output, since the factor $e^{10}$ cancels in softmax.

3Scaling and batching without mixing examples

3.1 Why divide by the square root?

Suppose query and key coordinates are independent, zero-mean, with variance $\sigma^2$. Each product has variance $\sigma^4$, and summing $d_k$ independent products gives variance $d_k\sigma^4$. Dividing by $\sqrt{d_k}$ gives variance $\sigma^4$. This is an initialization-scale argument; trained coordinates need not satisfy the assumptions exactly.

For two scores $[0,8]$, softmax is approximately $[0.000335,0.999665]$. Dividing by $\sqrt{64}=8$ instead gives $[0,1]$ and probabilities $[0.268941,0.731059]$. The second distribution has more room for score changes to alter its weights. Scaling limits dimension-driven saturation; it does not prohibit a trained head from becoming selective.

3.2 The full matrix operation

$$Y=\operatorname{softmax}_{\text{keys}}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V.$$

Rows are queries, columns are keys. Every row sums to one; columns generally do not. For a batch, transpose only the final two dimensions of $K$. Each batch item has its own attention matrix:

Check 2 · Find the wrong axis

For scores shaped [2,3,3], why is softmax(dim=-1) correct? What would dim=0 do?

Reveal the answer

The final axis enumerates keys for each query. Dimension 0 normalizes across the two examples, coupling their weights and making an example's output depend on its batch companion. Neither queries nor separate examples should compete for a row's probability mass.

4Multiple heads: separate routing decisions

One head produces one distribution over positions for each query. Two heads can retrieve two different mixtures at the same position. For example, one might emphasize a subject and another a nearby modifier. Heads are jointly trained; they are not independent language models voting on a final answer, and useful specialization is not guaranteed.

With model width $D$ and $H$ heads, take $d_h=D/H$. Each head has query, key, and value width $d_h$. Concatenating $H$ outputs recovers width $D$; an output projection $W_O\in\mathbb R^{D\times D}$ mixes the head features.

$$Y=\operatorname{Concat}(Y^{(1)},\ldots,Y^{(H)})W_O.$$

At $D=8,H=2$, each head returns 4 features. Ignoring biases, the three projection families contain $3D^2=192$ parameters and $W_O$ adds $D^2=64$, totaling 256. Changing the head count while holding $D$ fixed changes head width but not this parameter count.

4.1 Fused projection is the same algebra

Store $W_{QKV}=[W_Q\;W_K\;W_V]\in\mathbb R^{D\times3D}$. One multiplication $XW_{QKV}$ returns three adjacent feature groups. Split them, then reshape and transpose to [B,H,T,d_h]. This combines operations; it does not force $Q=K=V$.

Attention weights now have shape [B,H,T,T]. Arithmetic for the score/value products stays proportional to $BT^2D$ at fixed width, but explicitly storing all heads' weights takes $BHT^2$ entries. Similar arithmetic cost does not imply identical activation memory.

Check 3 · Rank and head width

For $T=3,D=8,H=2$, what is the maximum rank of a head output matrix and of the concatenated, projected output?

Reveal the answer

A head is $3\times4$, so rank is at most $\min(3,4)=3$. The combined output is $3\times8$, so rank is at most 3 too. In general the head bound is $\min(T,d_h)$, and the combined bound is $\min(T,D)$. These are upper bounds, not promises of full rank. $W_O$ cannot raise the rank of its input.

5Build a block: mix positions, then transform features

Attention mixes information across positions. The feedforward network transforms the resulting features independently at each position, with shared parameters:

$$\operatorname{FFN}(x)=f(xW_1+b_1)W_2+b_2,\quad W_1\in\mathbb R^{D\times D_{ff}},\quad W_2\in\mathbb R^{D_{ff}\times D}.$$

The FFN can expand to $D_{ff}=4D$, apply a nonlinear activation, then return to width $D$. “Position-wise” does not mean context-free: its input already contains information retrieved by attention. It means the FFN itself does not communicate between rows. A linear-only pair would collapse to a single linear map; the intervening nonlinearity matters.

5.1 Two arrangements you should recognize

The post-norm block in slides 25–26 computes:

$$U=\operatorname{LN}(X+\operatorname{MHA}(X)),\qquad Y=\operatorname{LN}(U+\operatorname{FFN}(U)).$$

A pre-norm version computes:

$$U=X+\operatorname{MHA}(\operatorname{LN}(X)),\qquad Y=U+\operatorname{FFN}(\operatorname{LN}(U)).$$

Both keep the residual width equal to $D$. LayerNorm normalizes across features within a token, not across sequence positions or batch items. In pre-norm, each update has an explicit identity path: $d(x+g(\operatorname{LN}(x)))/dx=I+J_{g\circ\operatorname{LN}}$. This helps gradient flow through a deep stack, but does not guarantee stable training under every initialization or learning rate. Revisit Handout #8 for the underlying optimization ideas.

Check 4 · Which operation communicates?

If you change one row of a block input, which operations can directly change another row? Would replacing LayerNorm by a normalization across token positions preserve that answer?

Reveal the answer

Attention can change another row. The shared FFN, feature-wise LayerNorm, and residual addition cannot directly do so. Normalizing across positions would couple rows and, in a causal model, could leak future-token information even if attention were masked.

6Depth, positions, and a vocabulary head

Stacking blocks lets later layers retrieve and transform features that earlier layers built. After $L$ blocks, the shape is still [B,T,D]. Apply a vocabulary projection to obtain [B,T,Vocab] logits. If input and output embeddings are tied, the logits for row $h_i$ are $h_iE^\top$ with $E\in\mathbb R^{Vocab\times D}$. Tying is a parameter-sharing choice, not a requirement of attention.

6.1 A precise statement about order

Unmasked self-attention without position information is permutation equivariant: reordering input rows reorders output rows the same way. It is not invariant: outputs do move. Let $P$ permute rows. Then scores become $P(QK^\top)P^\top$, row-wise softmax is permuted in the same way, and multiplying by $PV$ yields $PY$. Shared FFNs and token-wise normalization preserve this property.

Thus an unrestricted block cannot tell that a row was originally “first” just from its array index. Adding position vectors $p_i$ makes $x_i=E[w_i]+p_i$. The same token at two positions now starts with different vectors. Learned absolute embeddings add $T_{max}D$ trainable parameters; fixed sinusoidal encodings do not. In the sinusoidal scheme, even/odd feature pairs use sine and cosine at different frequencies.

The mask also introduces structureA causal mask treats earlier and later indices differently, so the unrestricted permutation proof does not apply unchanged. The mask supplies an ordering constraint. Explicit position encodings still give the model a direct signal for positions or distances; mask structure and positional embeddings play different roles.
Check 5 · Same token, different position

Without position information, two identical input rows have identical queries. Under unrestricted attention, must their outputs match? What changes if they have different causal masks?

Reveal the answer

Yes: they see the same keys and values with the same scores, so their mixtures match. With different causal masks, their allowed key sets differ and outputs need not match. Adding different positional vectors also breaks the identical-query premise.

7One predictor, two execution modes

7.1 Generation appends one token at a time

Given a prompt, use the logits at its final real position to predict the next token. Sample from softmax, or select the largest logit for greedy decoding; append the chosen token and repeat. Stop at EOS or a chosen length bound. The vocabulary projection is shared across positions. Generation is sequential because the next input depends on the token just chosen.

Extending the prompt changes the next-position prediction. In a correctly causal model, earlier positions' representations do not change merely because a later token was appended, with positions and other settings fixed. That property will justify caching in Handout #12. No cache is needed to understand the generation algorithm; a naive implementation recomputes the growing prefix.

7.2 Training supplies all gold prefixes together

For the cat sat on the mat <eos>, use:

Inputthecatsatonthemat
TargetcatsatonthematEOS

Output at input position $i$ predicts the token at $i+1$. The input token at $i$ is legitimate context. The target at $i+1$ is not. This is teacher forcing: training uses the observed prefix rather than a prefix sampled by the model. All target positions are known, so their losses can be computed together:

$$\mathcal L=-\frac1N\sum_{b,i\;\text{scored}}\log p_\theta(w_{b,i+1}\mid w_{b,\le i}).$$

Backpropagation updates embeddings, Q/K/V and output projections, FFNs, and trainable normalization and position parameters. Queries, attention weights, and intermediate representations are activations, not independently optimized parameter tables. The softmax function itself has no trainable parameters.

7.3 Why shifting the targets is insufficient

The target “cat” also appears in the input, one column to the right. With unrestricted attention, the “the” query can access the “cat” key and value. A low training loss could then reflect learning to read the answer from the future, a route unavailable during generation. The same problem recurs at every position except the last.

A causal model must enforce that every output at $i$ depends only on inputs at positions $j\le i$. Enforce this in every block: masking only the final block is insufficient because an earlier block could already have copied future information into an allowed row. Handout #12 derives the mask and tests this dependence directly.

Check 6 · Leakage audit

A two-block model has unrestricted attention in block 1 and causal attention in block 2. Is the output at position 0 safe? Does removing the loss at position 1 fix it?

Reveal the answer

No. Block 1 can copy input 1 into representation 0; block 2 can attend to representation 0 and use that future information. Removing a loss does not remove its corresponding input or the information path. Restrict all attention blocks and keep other operations token-wise.

8Lab: verify attention before building an LM

Download 11_attention.py and run python 11_attention.py with PyTorch installed. This original lab has no training loop: it isolates retrieval, fused projections, and the order symmetry. It prints the worked answer $[2,1.5]$ and checks row sums, shapes, projection equivalence, permutation equivariance, and future dependence.

def attention(q, k, v):
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
    weights = scores.softmax(dim=-1)
    return weights @ v, weights

Notice that transpose(-2,-1) works for both three-dimensional batches and four-dimensional head tensors. .T does not express that operation for arbitrary batch rank.

Lab edits · Make and explain a failure
  1. Replace softmax(dim=-1) by softmax(dim=-2). Which assertion catches it, and what is now normalized?
  2. Add different position vectors before mha. Compare mha(x[:,perm] + positions) with the permuted output of mha(x + positions). Why does the old equality no longer follow?
  3. Set all values to the same vector. Can changing scores change the output before $W_O$?
Reveal the answers

1. The row-sum check catches the wrong normalization; queries now compete within each key column. In the one-query example, the wrong softmax also gives all weights 1 and output $[6,6]$. 2. Token rows move but position vectors stay assigned to indices, so the combined inputs are not simply permuted versions of one another. 3. No: $\sum_j a_jv=v$. Routing cannot create information absent from the values.

9.1 Identify the head axis

model.py · CausalSelfAttention.forward · verbatim excerpt

        q, k, v  = self.c_attn(x).split(self.n_embd, dim=2)
        k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
        q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)
        v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)

C is our $D$, nh is $H$, and hs is $d_h$. The projection fuses all three families; the reshape separates heads. The output later transposes back and joins head features, as in §4.

9.2 Recognize pre-norm

model.py · Block.forward · verbatim excerpt

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x

This is §5's pre-norm arrangement. Inside MLP, trace the expansion to 4 * config.n_embd, GELU, and contraction back to $D$. The implementation also includes dropout; our lab disables that complication.

Code edit · One axis breaks head layout

In a local copy, remove the three .transpose(1, 2) calls and force the manual attention branch. With $B=2,T=3,C=8,H=2$, what shape does the score matrix have instead of [2,2,3,3]? Predict the failure, then run it.

Reveal the answer

Each Q/K tensor remains [2,3,2,4], giving scores [2,3,2,2]. The operation mixes heads at each token instead of tokens within each head. The manual causal mask is [1,1,3,3], so masking fails on incompatible final dimensions. Restore the transposes; reshaping alone does not exchange axes.
