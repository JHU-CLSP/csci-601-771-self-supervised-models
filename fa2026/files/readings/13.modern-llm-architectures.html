1Read an architecture as a set of choices

Start by separating the information boundary from the computation inside it. A decoder's causal attention defines what each prediction can read. LayerNorm versus RMSNorm changes how features are scaled; SwiGLU changes a token-wise transformation. Neither change allows a query to read future tokens. A parallel block changes dependencies within a layer, not the next-token objective.

For the topology recap, identify which sequence each query reads. An encoder represents an observed sequence with bidirectional self-attention. A decoder uses causal self-attention to generate a sequence. An encoder–decoder combines a bidirectional source encoder, a causal target decoder, and target-to-source cross-attention. “Bidirectional source” does not mean the decoder may read future target tokens.

Practice · Choose the information boundary

Extends Spring 2025 Quiz 2 Q4.1, pp. 6–7.

Match BERT, T5, and GPT to the three topologies. For each, name an information source available to a query. Why would an encoder-style representation of the complete target sentence leak information in next-token training?

Reveal the answer

BERT is encoder-only: a query can read both earlier and later positions in its supplied input. T5 is encoder–decoder: a target query can read its target prefix and the encoded source. GPT is decoder-only: a query reads its input prefix. Encoding a complete target sequence bidirectionally can expose the very next token being predicted. The topology names describe attention structure; they do not alone specify the loss, corruption scheme, or downstream task.

Predict first · A causality audit

A causal decoder changes to RMSNorm and SwiGLU, but a programmer computes the RMS across both time and features. Can the model still leak future information?

Reveal the answer

Yes. The denominator for row $i$ now depends on future activations, even with causal attention. Use mean(dim=-1, keepdim=True), and repeat #12’s suffix-change/prefix-logit test. Architectural names cannot replace a dependence test.

2Normalization: where it sits and what it removes

2.1 Follow the gradient through the residual stream

Let $S$ be an attention or FFN sublayer and $N$ a normalization. Using column vectors, let $J_y=\partial y/\partial x$; each sublayer Jacobian below is evaluated at its own input:

$$\text{pre-norm: } y=x+S(N(x)),\qquad J_y=I+J_SJ_N;$$ $$\text{post-norm: } y=N(x+S(x)),\qquad J_y=J_N(I+J_S).$$

The original Transformer used post-norm. In pre-norm, one path from $x$ to $y$ bypasses both $N$ and $S$. If the sublayer contributes zero, the block is exactly the identity. In post-norm, even a zero sublayer leaves $N(x)$. The shortcut itself passes through the normalization Jacobian. Across many pre-norm blocks, expanding the product of their Jacobians includes an identity contribution.

This is a statement about a path, not a promise about the total gradient: branch derivatives can reinforce or cancel it. A final normalization, output head, and loss still affect gradients. Pre-norm decoders commonly normalize again before the vocabulary projection.

What the evidence supportsXiong et al. (2020) analyze initialization and find less problematic gradient scales for pre-norm in their setting. Their experiments motivate reduced reliance on warm-up; this does not prove every pre-norm model can use any learning rate without warm-up.
Predict first · Turn off the sublayer

Set $S(x)=0$. For $x=[1,2,3,4]$, what do pre-norm and post-norm return? Which preserves a common shift $x\mapsto x+5\mathbf1$ in its output?

Reveal the answer

Pre-norm returns $x$, so its output shifts by $5\mathbf1$. Post-norm with LayerNorm, unit gain, zero bias, and small epsilon returns approximately $[-1.34164,-0.44721,0.44721,1.34164]$. This result is unchanged by a common input shift. The lab verifies the pre-norm Jacobian is $I$ and the post-norm LayerNorm Jacobian annihilates the common-shift direction.

Optional depth · Read the other normalization layouts on slide 10

The output-norm schematic normalizes the branch result: $y=x+N(S(x))$. The sandwich schematic normalizes both its input and output: $y=x+N_{\rm out}(S(N_{\rm in}(x)))$. Both leave the residual bypass outside normalization, unlike post-norm. “Output-norm” here refers to a sublayer branch, not the final normalization before the vocabulary head. The slide 11 QK-norm annotation concerns the query/key tensors used in attention scores; it is a separate choice from normalizing the residual stream.

2.2 LayerNorm and RMSNorm preserve different information

For one token's vector $x\in\mathbb R^D$, define $\mu=D^{-1}\sum_jx_j$ and $\sigma^2=D^{-1}\sum_j(x_j-\mu)^2$. Standard affine LayerNorm and the bias-free RMSNorm used here are:

$$\operatorname{LN}(x)_j=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j,$$ $$\operatorname{RMS}(x)_j=\gamma_j\frac{x_j}{\sqrt{D^{-1}\sum_kx_k^2+\epsilon}}.$$

Both learn a per-feature gain $\gamma$. RMSNorm omits mean subtraction and the usual LayerNorm bias $\beta$. Its denominator is a second moment, not a centered variance. The identity $D^{-1}\sum_jx_j^2=\sigma^2+\mu^2$ shows exactly what differs.

With $\gamma=1$, $\beta=0$, and negligible epsilon, $[1,2,3,4]$ becomes $[-1.342,-0.447,0.447,1.342]$ under LN, but $[0.365,0.730,1.095,1.461]$ under RMSNorm. LN removes a common offset; RMSNorm preserves its influence on direction. Multiplying a nonzero vector by a positive scalar approximately preserves both normalized outputs; epsilon prevents exact scale invariance near zero. A negative scalar reverses their normalized components before any affine bias.

Practice · What exactly is normalized?

Adapted from Spring 2025 HW6 §1.8, p. 3 and Quiz 2 Q4.10–11, p. 8.

For input shape $[2,5,8]$, how many statistics does token-wise RMSNorm compute? How many learned scalars does it have? Does normalization occur between layers? What does epsilon protect against?

Reveal the answer

Ten second moments, each over 8 features; 8 shared gain parameters. Standard affine LN would have 8 gains and 8 biases. These layers normalize each token's feature vector, not “between layers” or across batch examples. Epsilon keeps the denominator nonzero for a zero vector and limits amplification near zero; for RMSNorm it is added to the second moment, not to a variance.

After learned gains/biases, LN need not have exactly zero mean or unit variance. RMSNorm does not center at all. Neither guarantees that every feature has equal influence on the next layer.

2.3 A precision detail that the formula hides

Squaring large float16 activations can overflow even when the final normalized answer would be small. Accumulate the second moment in float32 for float16/bfloat16 inputs, then cast the normalized result back. Preserve float64 if using it for derivative checks. Here is the core of the lab's RMSNorm; its weight is an nn.Parameter initialized to ones.

work = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
unit = work * torch.rsqrt(work.square().mean(-1, keepdim=True) + self.eps)
return unit.to(x.dtype) * self.weight.to(x.dtype)

keepdim=True makes the denominator shape $[B,T,1]$, so broadcasting rescales each token. A persistent gain must be registered on the module, not recreated inside forward. This is clear teaching code; production kernels may fuse operations and use different precision policies.

2.4 Few FLOPs can still cost time

Connect the slides' runtime question to #12’s arithmetic-versus-IO distinction: a matrix multiply has high data reuse, while normalization involves reductions, reading/writing activations, and kernel launches. The percentage of total arithmetic does not determine the percentage of elapsed time. RMSNorm removes some operations, but kernel fusion and memory traffic determine the realized speedup. Its missing $D$ bias parameters are tiny compared with a $D\times F$ FFN matrix.

Predict first · A runtime sanity check

Normalization is 10% of measured execution time. A replacement makes normalization twice as fast and changes nothing else. What is the whole-model speedup? Does a 0.2% FLOP share rule out the measured 10% time share?

Reveal the answer

New time is $0.9+0.1/2=0.95$ of the original: speedup $1/0.95\approx1.053$, about 5.3% more throughput. It does not halve total runtime. FLOP share cannot rule out the time share because operations differ in hardware efficiency and IO. Benchmark the full workload with warm-up and device synchronization, not only an isolated Python call.

Further context: Zhang & Sennrich (2019), RMSNorm. The invariance examples and runtime exercise above are worked derivations.

3Gated FFNs: more projections, a fairer comparison

3.1 A smooth activation is not a random procedure

ReLU is $\max(0,z)$; exact GELU is $z\Phi(z)$, with $\Phi$ the standard normal CDF. At $z=-1$, ReLU is 0 but GELU is approximately −0.158655. GELU's Gaussian interpretation does not make an ordinary GELU forward pass stochastic: identical inputs give identical outputs. Libraries may also offer a tanh approximation, so check the chosen implementation when comparing numbers.

Practice · Different negative-side behavior

Adapted from Spring 2025 Quiz 2 Q4.2, p. 7.

Define ReLU and GELU, then explain why “GELU keeps all negative signals” and “GELU samples a random Gaussian mask” are both misleading.

Reveal the answer

GELU multiplies by a deterministic CDF value in $(0,1)$ for finite inputs; very negative values are strongly attenuated toward zero, rather than preserved unchanged. No Gaussian draw is needed. ReLU makes all negative activations exactly zero. Smoothness alone does not establish which activation trains a particular model best.

3.2 Trace both views of one token

Use row vectors for FFN equations. A bias-free dense FFN is $f(xW_1)W_2$, with $W_1\in\mathbb R^{D\times F}$ and $W_2\in\mathbb R^{F\times D}$. A gated FFN has two input projections:

$$g=xW_g,\quad u=xW_u,\quad z=f(g)\odot u,\quad y=zW_d.$$

For SwiGLU, $f(g)=\operatorname{SiLU}(g)=g\operatorname{sigmoid}(g)$; for GeGLU, $f$ is GELU. The multiplication is elementwise, not a dot product. Each hidden coordinate's response depends on two learned views of the same input token. All tokens use the same matrices.

The gate can be negative, and SiLU(2) is about 1.762, so “volume knob” does not mean a probability constrained to $[0,1]$. Nor is the gate shared across tokens: matrices are shared, but their outputs depend on each token.

class SwiGLU(nn.Module):
    def __init__(self, d, hidden):
        super().__init__()
        self.gate = nn.Linear(d, hidden, bias=False)
        self.up = nn.Linear(d, hidden, bias=False)
        self.down = nn.Linear(hidden, d, bias=False)

    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))
Predict first · Two plausible-looking bugs

Why are F.silu(gate(x) * up(x)) and F.silu(gate(x)) @ up(x).transpose(-1, -2) different from SwiGLU?

Reveal the answer

The first changes the nonlinearity's argument: generally $f(g\odot u)\ne f(g)\odot u$. The second makes a $[B,T,T]$ product from $[B,T,F]$ inputs, mixing tokens and discarding the intended hidden-feature axis. It may even create future dependence. Correct hidden shape stays $[B,T,F]$, and the down-projection returns $[B,T,D]$.

3.3 Match parameters before judging the gate

Ignoring biases, dense FFN parameters are $2DF_{\rm dense}$; gated FFN parameters are $3DF_{\rm gated}$. Equating these gives:

$$F_{\rm gated}=\frac23F_{\rm dense};\qquad F_{\rm dense}=4D\Longrightarrow F_{\rm gated}=\frac83D.$$

For $D=768$, dense width 3072 and gated width 2048 each use 4,718,592 parameters. Keeping gated width 3072 gives 7,077,888: 50% more FFN parameters. A quality gain in that comparison could partly be a budget gain. Forward projection arithmetic is also matched when the two different hidden widths obey this equation: approximately $2BT$ times the matrix parameter count, counting a multiply and add as two FLOPs. Activation operations and saved intermediates still differ.

Experiment: what budget did you actually match?

Counts exclude biases, normalization, attention, and embeddings. This is an FFN budget, not a whole-model memory or speed estimate.

Real implementations often round hidden widths to hardware-friendly multiples. Report the actual width and actual count; “roughly two thirds” is not an exact equality after rounding. Removing the dense biases saves only $F+D$ parameters: at $D=768,F=3072$, that is 3,840 versus 4.72 million matrix entries.

Evidence and a fair experimentShazeer (2020) compares GLU variants under matched projection budgets. To evaluate your own change, fix data, tokenizer, training tokens, and optimizer settings; state whether you match parameters, arithmetic, or elapsed training time. Compare validation loss across seeds and record throughput/peak memory separately. A runnable shape check is not a quality benchmark.

4Serial versus parallel: find the missing dependency

Write both formulations with explicit intermediates. $A$ is attention and $M$ the FFN:

$$\text{serial: } h=x+A(N_1(x)),\qquad y=h+M(N_2(h));$$ $$\text{parallel (shared norm): } n=N(x),\qquad y=x+A(n)+M(n).$$

In serial, the FFN sees attention's update from this block. In parallel, both branches read the original normalized stream. Attention information can reach a later block's FFN, but there is no attention-to-FFN edge inside the current block. Changing this edge generally changes the function, even if the parameter values are identical.

Equation clarificationPrinted slide 29 (PDF page 28) currently shows h + MLP(LN(x)) + Attention(LN(x)) under “parallel.” If $h$ has the serial definition above it, this adds the attention update twice. The residual term should be $x$, not that serial intermediate $h$. The shared-input explanation on the slide corresponds to $x+A(N(x))+M(N(x))$, used here. The deck itself is left unchanged.

4.1 A small counterexample to “same computation, new schedule”

To isolate the dependency, use $x=[1,2,3,4]$, affine-free LN with epsilon $10^{-6}$, $A(z)=[z_0,0,0,0]$, and $M(z)=z$. These toy branches are not an attention implementation. The same functions give different outputs; the lab computes both:

Some parallel designs use separate branch norms, so a shared norm is an explicit choice here.

Practice · Architecture versus implementation speed

Explain which edge is removed by a parallel block. Does it have half as many FFN/attention parameters? Must it improve quality or produce a 15% speedup on your laptop?

Reveal the answer

It removes the within-block attention-update → FFN-input edge. With equal branch widths, attention/FFN matrix counts remain the same; this shared-norm variant removes one normalization module. Parallel branches also do not remove autoregressive token dependencies. A model still needs the sampled next token before predicting the one after it.

5Embedding tying is a constraint on learning

5.1 Shapes and actual sharing

An embedding matrix $E\in\mathbb R^{V\times D}$ maps token ID $i$ to row $E_i$. For final row-vector hidden state $h\in\mathbb R^D$, tied logits are $hE^\top\in\mathbb R^V$. In mathematical notation the output matrix is transposed; in PyTorch both nn.Embedding(V,D).weight and nn.Linear(D,V).weight are stored as $[V,D]$. Assign the same Parameter without transposing it.

self.embed = nn.Embedding(vocab, d)
self.head = nn.Linear(d, vocab, bias=False)
self.head.weight = self.embed.weight
# Tie during construction, before creating the optimizer.
assert self.head.weight is self.embed.weight

Copying values using copy_ or wrapping a detached clone in a new Parameter leaves two independently trainable objects. They can start equal and diverge on the first step. Use model.parameters() to enumerate the registered shared parameter once; do not concatenate overlapping module parameter lists into the optimizer. Replacing a parameter after constructing the optimizer can leave the optimizer tracking an obsolete object.

Tying is a modeling constraint, not merely compression: input and output roles must agree on one representation. Separate weights allow more independent choices. Tying also requires compatible hidden widths (or an extra adapter). A separate output bias is possible, but omitted here.

5.2 Why a token absent from the input can still update

For one prediction, let $p_j$ be the softmax probability of vocabulary item $j$ and $t$ its target ID. Holding $h$ fixed, the output-side derivative is:

$$\left.\frac{\partial\ell}{\partial E_j}\right|_{\rm output}=(p_j-\mathbf1[j=t])h.$$

The embedding-lookup route contributes only to rows looked up as inputs. The output route has a coefficient for every vocabulary row under full softmax, including rows absent from the input. Under tying, autograd sums both routes into the same gradient buffer:

$$\nabla_E\ell=\nabla_E\ell\big|_{\rm input}+\nabla_E\ell\big|_{\rm output}.$$

“Dense signal” is not a guarantee every row has a nonzero or helpful update: zero hidden states, numerical underflow, cancellation, or modified objectives can change that. In a single ordinary full-softmax prediction with nonzero $h$, an absent, non-target word gets coefficient $p_j>0$. Holding $h$ fixed, the output-side gradient descent update lowers that word’s logit. With multiple predictions or a changing hidden state, individual logit changes need not all have this sign. It learns from being an alternative prediction, not from being observed as input.

Predict first · The unused row

A five-token toy model reads IDs [0,0] and predicts targets [1,2]. Row 4 is neither read nor a target. Which gradient routes reach row 4? How would you verify that tying sums the routes?

Reveal the answer

Lookup contributes zero for row 4; the full-softmax output route generally contributes a nonzero gradient. Make two independent matrices initialized identically, compute their two gradients, and compare their sum with the tied model's gradient. The supplied lab performs exactly this comparison at the same initial weights and on the same loss.

5.3 Count savings without promising fewer logits

Untied input/output matrices contain $2VD$ parameters; tied matrices contain $VD$, saving $VD$. For $V=32{,}000,D=768$, this saves 24,576,000 parameters, or 46.875 MiB of two-byte weights. Under an illustrative training layout with a two-byte weight, two-byte gradient, and two float32 Adam moments, saving 12 bytes per parameter gives 281.25 MiB. A float32 master copy would add another 93.75 MiB. Actual optimizer, sharding, and dtype policies determine the real memory.

The logits still require a projection into $V$ classes. Tying does not remove the $[B,T,V]$ output, vocabulary softmax, or their arithmetic. The saved parameter fraction depends on depth and width of the rest of the model. Press & Wolf (2017) motivate sharing and study its language-modeling benefits; equal roles are an inductive bias, not a mathematical necessity for every model.

8Practice: diagnose the claim, then design the check

A · “Normalization has no parameters”

A student implements RMSNorm using an ordinary tensor for the learned gain, created inside forward. Outputs look sensible. What check catches the problem?

Reveal the answer

Inspect named_parameters(), verify a persistent gain of shape $[D]$, and check its gradient and update after a backward/optimizer step. A plausible forward output does not prove the gain is registered or trainable. Create an nn.Parameter in __init__.

B · “SwiGLU improved perplexity”

A dense FFN with $F=4D$ is replaced with a gated FFN of the same hidden width. List one budget change and two observations needed to evaluate the result.

Reveal the answer

FFN matrix parameters and projection arithmetic rise by 50%. Compare a gated width near $8D/3$ under the stated budget, then measure validation loss and throughput/peak memory with controlled data and training settings. Multiple seeds help distinguish a reproducible effect from one run. Matching hidden width is not matching parameters.

C · “Parallel gives the FFN more context”

Does a parallel block's FFN receive this block's attention result? Can it still transform information gathered by earlier attention blocks?

Reveal the answer

It does not receive the current block's attention result. Its input residual stream can already contain contextual information from preceding blocks. Within-layer independence does not mean the FFN sees only raw token embeddings at every depth.

D · “Tying prevents rare-word updates”

A vocabulary item never appears as an input in this batch. Is its tied row necessarily unchanged after a step? Does sharing guarantee a better rare-word representation?

Reveal the answer

No: the full-softmax output route can update it. Sharing exposes the row to both roles, but signal availability alone does not guarantee representation quality. Check both gradient routes at identical initial weights, as in §5.2 and the lab.

E · “Everything got faster because there are fewer parameters”

Your changes remove FFN biases, switch to RMSNorm, and tie embeddings. Which saves a $VD$ matrix? Which changes normalization statistics? What evidence supports an end-to-end speed claim?

Reveal the answer

Tying saves the vocabulary-sized matrix; RMSNorm replaces centered variance with a second moment. Bias removal saves vector parameters. Profile and time the full intended workload with the same batch/context, dtype, device, compiler, and synchronization; compare validation quality and memory too. Parameter counts alone do not establish elapsed-time savings.
